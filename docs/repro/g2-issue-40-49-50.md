### 1.1 可验证的断言

### 1.4 真正的缺陷不是"太严"，而是"4 个原因共用 1 句文案"

`backupUnrecognized` 在 `checkArchiveFormat` 里有 **3 个**抛出点（`:58`、`:63-64`、`:72`），另有 1 个近似原因走另一个 key（`:69-71` 的 `backupIncomplete`）。而落盘只有 `error.msg / error.name / error.stack`（`services/diagnostics/collector.ts:150-163`）：

```ts
150: export const errorMeta = (error: unknown): LogMeta => {
151:   const meta: LogMeta = { 'error.msg': truncate(redact(safeString(error)), MAX_META_LENGTH) }
152:   if (error instanceof Error) { meta['error.name'] = error.name; ... }
```

**没有 `check.failedRule` / `check.expected` / `check.found`**，所以"用户到底哪一段校验失败"在现有日志里**原理上不可回答**——这正是 #40 评论 1 定的唯一下一动作。

### 1.5 评论 2 的"带图片就整包失败"与 #40 不是同一条路径

`check` 阶段（`importArchive.ts:57-73`）在读第一个条目后**立即 `return`**，会话 JSON、`chat_session_index.json`、图片条目都没有被读取；`#40-A`（3 会话、无图）与 `#40-C`（目录条目前置）均 `ok:true`，`#40-D/E/F` 均在 `sessionsStaged:0` 时失败。也就是说：**图片数量/内容不可能改变 `check` 的判定结果**。评论 2 描述的是 `staging` 阶段的现象，属于 #50（§3），不应回填为 #40 的根因。

### 1.6 #40 修复方案（≤5 项）

1. **结构化诊断**：`checkArchiveFormat` 在抛错前带 params —— `fail('backupUnrecognized', { rule:'firstEntryNotManifest', expected:'manifest.json', found: entry.path, entries: n, bytes: file.size })`；`backup.ts` 的 `recordAction('import_error', …)` 增设 `check.failedRule / check.expected / check.found`（`services/chat/backup.ts:91-99`）。
2. **与物理顺序解耦**：先 `listArchivePaths(file)`（`zipReader.ts:235-241` 已有）判断 `manifest.json` 是否存在并读版本，再进入流式导入；顺序只作为提示，不作为拒绝条件。
3. **文案分级**：`notZip`（保留"无法识别该文件…"）/ `missingManifest`（"这不是 DeepSeek 导出的历史对话（缺少 manifest.json）"）/ `emptyArchive`（"文件是空的或下载被截断"）/ `newerVersion`（已存在 `backupNewerVersion`）。
4. **最小合法包契约 + 版本矩阵**：写进 `docs/`（`manifest.json` 必须存在且 `export_format_version === 3`；条目集合与命名规则；条目/Session 数量与字节上限；哪些顺序被容忍）。
5. **真机回归**：用真实 6.25MB 包复跑 `import_error`，确认新增字段能落到 `firstEntryNotManifest` 或 `notZip`；再按 §1.2 的 6 个变体加集成测试（禁止只测"合法包能导入"）。

### 2.4 #49 修复方案（≤5 项）

1. **分支降级而非抛错**：`buildTree` 遇到悬空 `parent_id` → 截断该消息及其子树（或重挂到根）；`current_message_id` 不存在 → 回退到 id 最大的消息；角色不交替 → 按 id 顺序重挂。返回 `{ messages, rootMessageId, droppedMessages: n, reasons: [...] }`。
2. **会话级隔离**：`importArchive` 每个会话一个 `try/catch`，捕获 `BackupError` → 记 `skipped.push({ id, title, reason, messageId? })`，继续下一个会话；只有容器级错误（`isZipFile` / manifest / index 缺失）才整包失败。
3. **部分成功语义**：`importArchive` 返回 `{ imported: number, skipped: SkippedSession[] }`；`importHistory` / `importHistoryFromUrl` 的返回值从 `count` 扩成该对象；界面提示"成功 N 个会话，跳过 M 个（可展开明细）"；`import_error` / `import_done` 日志带 `skipped` 计数。
4. **错误可定位**：`fail('backupInvalidBranches', { sessionId, sessionTitle, messageId, parentId })`，文案带占位符（`zh.ts:97` 改为可带参数的句子）。
5. **测试**：新增集成用例覆盖悬空 `parent_id` / 坏 `current_message_id` / 角色冲突，断言"其余会话导入成功 + skipped 明细正确 + 不触发 `clearStaging` 全丢"。


   导出侧的顺序是 `manifest → 全部会话 → index → 全部图片`（`exportArchive.ts:11`、`:48-49`），但**只要图片提前到 index 之前**（例如服务端换了写出顺序、或包被重打包成"会话+图片"分批），就落进 `else` → 整包失败，而实际文件一个字节都没坏。`format.ts:17` 把该顺序写成了隐性契约。
3. **非 `BackupError` 一律冒泡**：`importArchive.ts:158-159` 只翻 `ArchiveError`；`db.saveStagingFiles`（`db.ts:205-206`）的配额/IO 失败是 `DOMException`，会原样穿过 `backup.ts:91-99` 与 `urlImport.ts:861-875`，最后被 `SettingsDialog.tsx:780` 的 `catch {` 吞掉 → 用户只看到"可能是文件格式错误"。**这条路径本地无法复现**（无 IndexedDB 环境），仅代码链路确定。
4. **没有"跳过 N 张图片"的出口**：`saveImage` 只在真正写入时推进度（`importArchive.ts:112` `images: stored.size`），未被引用/被跳过的图片没有任何计数；`skipEntry`（`:152`）对用户不可见。

### 3.6 #50 修复方案（≤5 项）

1. **条目级隔离**：图片条目 `readEntry` 失败（CRC/长度）→ `skipEntry` + 记 `failedImages.push({ path, reason })`，不 fail 整包；收尾提示"N 张图片未能导入"。
2. **归属判定与顺序解耦**：一律用路径解析出的 session id 判 `imported.has(id)`，去掉 `currentSessionId` 分支；无法归属的条目按 `skipEntry` 记入 `ignoredEntries`，**只有"看起来是会话 JSON 却解析不了"才算不完整**（删掉 `:153-155` 的一刀切 `fail`）。
3. **存储错误分级**：`saveStagingFiles` 的配额/IO 失败包成可行动文案（如 `backupSpaceLow`），或在 `importArchive` catch 里把非 `BackupError` 包成 `backupStorageFailed`（保留 `cause`/stack），避免掉进通用文案。
4. **界面不吞错误**：`SettingsDialog.tsx:780 catch {` → `catch (error) { setStatus(errorStatus('historyImportFailed', error)) }`（`errorStatus` 已存在，`:418-424`）。
5. **测试**：三包对照（无图 / 完好图 / 坏图）+ 顺序变体，断言"无图与坏图都导入成功，且坏图被跳过并计数"。顺带确认 #32 的 `tests/fixtures/domain05/archive-fixture.mjs`（图片紧跟自己的会话、字节完好，等价本次 `#50-A`）**覆盖不到**坏图与错序两条路径 —— 这就是 #32 一直没抓到 #50 的原因。
