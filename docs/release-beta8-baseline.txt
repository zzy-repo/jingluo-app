## 2. 本次要修的两条用例：修复前失败原文（纯净 beta7 d593312）

### tests/integration/provider-channels.test.mjs

```
  ✗   我们的渠道 缺少「深度思考」入口
  ✗   我们的渠道发消息 URL 不对：http://62.106.70.167:60010/v1/chat/completions
  ✗   我们的渠道 x-api-key 头不对：undefined
  ✗   console 有 2 条 error：Failed to load resource: the server responded with a status of 401 (Unauthorized) | Failed to load resource: the server responded with a status of 401 (Unauthorized)
  ✗ 我们的渠道 缺少「深度思考」入口
  ✗ 我们的渠道发消息 URL 不对：http://62.106.70.167:60010/v1/chat/completions
  ✗ 我们的渠道 x-api-key 头不对：undefined
  ✗ console 有 2 条 error：Failed to load resource: the server responded with a status of 401 (Unauthorized) | Failed to load resource: the server responded with a status of 401 (Unauthorized)
```

根因：用例仍按旧 Anthropic 契约断言（`123.207.199.196:60010` + `/v1/messages` + `x-api-key` + 深度思考），
而 beta7 起产品契约是 `62.106.70.167:60010` + `/v1/chat/completions` + `Authorization: Bearer`、无 thinking。
打桩路由还停在旧地址，于是 ours 的请求直接打到真网（401），console error 也跟着红。

### tests/integration/internal-build.test.mjs

```
  ✗   DeepSeek 官方渠道 已保存的 Key 没按掩码显示（输入框=1，掩码=false）
  ✗ DeepSeek 官方渠道 已保存的 Key 没按掩码显示（输入框=1，掩码=false）
  ✗ 用例异常：locator.waitFor: Timeout 20000ms exceeded.
```

根因同上，另多一条连带失败：「DeepSeek 官方渠道 已保存的 Key 没按掩码显示」——
保存 Key 会先探测 `/v1/models`，旧地址没被打桩 → 探测失败 → 编辑态不复位 → 掩码没显示。
**不是产品回归**：改成新地址打桩后该断言（原样保留）通过。

## 4. 断言没有被放宽

- 地址 / 路径 / 鉴权头 / 能力项按当前产品契约对齐，**每条原断言保护的东西都保留**：
  渠道隔离（DeepSeek 官方仍 `/anthropic/v1/messages`）、Key 不进界面/不进日志、内置模型不可改、
  不落 localStorage、请求体剥离 DeepSeek 扩展字段、console error = 0。
- 鉴权从「`x-api-key` 全等」换成「`Authorization` 必须全等 `Bearer <key>`」，并**新增**一条「不许再带 `x-api-key`」；
- 能力项从 `thinking: true` 改为 `thinking: false`（该协议不提供 thinking 入口），其余三项不变仍是「DOM 里必须没有」；
- 请求体里的 system 提醒，从 `body.system` 改为 OpenAI 协议真实位置 `messages[0].role==='system'`，
  断言内容不变（含 `Web`、无空段）。
