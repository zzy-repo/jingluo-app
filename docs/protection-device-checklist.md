# Storage Protection 真机 / 模拟器验收清单（#909）

**本期未执行。** 下面全部是待做项；单测只覆盖逻辑层（内存文件系统 + fake-indexeddb），没有任何一步经过真机或模拟器。
验收口径见 `docs/protection-snapshot-coverage.md`（覆盖范围 / RPO / 不可恢复边界）。

前置：Android 构建含 `AppFileSystemPlugin`（#907）；`adb` 可用；测试机上有若干条带图片的会话。
所有步骤只在测试设备上做。造满盘与删库会毁掉该设备上该应用的数据，**先导出备份**。

## A 快照与高水位正常写入
1. 新装，启动，建 3 条会话（其中一条带图片），每条发 2 轮。
2. `adb shell run-as <pkg> ls files/app-fs/snapshots files/app-fs/protection`（路径以插件实际目录为准）：
   - 应有私有目录下 protection 子目录里的 highwater 标记文件，`snapshots/<ts>.json` 至少 1 份；
   - 15s 内连续发送只出一份；切后台后立刻多出一份。
3. 打开最新快照：JSON 含 3 条会话文本；**不含**图片字节；`checksum` 字段存在。
4. 连续制造 7 次快照（每次间隔 >15s 或切后台）：只保留最近 5 份。
- 记录：快照写入耗时（logcat / 诊断日志）、快照文件大小。→ 回填 RPO 里「一次快照写入耗时」。

## B 满盘保护
1. 用大文件把分区填到剩余 < 64MB（`adb shell dd if=/dev/zero of=/data/local/tmp/fill bs=1M count=<N>`，注意目录要和应用私有目录同分区；用 `adb shell df /data` 确认）。
2. 回到应用发一条消息：应出现横幅「存储空间不足，新内容可能无法保存」（无重试按钮）。
3. 删掉填充文件，再发一条：横幅在 ≈10s 缓存窗口后消失。
4. 剩余空间恰好在阈值附近（63MB / 64MB）各试一次，记录是否符合 `<64MB 才升档`。
5. 观察：`freeBytes` 在该机型上是否返回数字（返回 undefined 时应保持原行为，不升档，也不能误报「足够」）。

## C 造「库被系统清除」（核心事故复现）
1. 在 A 的基础上，保持满盘（剩余 ≈0），持续发消息制造脏写。
2. 发送过程中 `adb shell am force-stop <pkg>` 杀进程。
3. 重新启动。Chromium 若判 `Corruption: checksum mismatch` 会整库删除；若这次没复现，重复 1–2 或改用：
   `adb shell run-as <pkg> rm -r app_webview/Default/IndexedDB`（模拟删库，**这不等于真实事故，只验证应用对「库没了」的反应**）。
4. 预期：
   - 不显示干净欢迎页；顶部横幅「本机的聊天记录已被系统清除（此前约有 N 条会话）」；
   - 列出快照（时间 · 会话数）；
   - 释放空间前重复启动多次：横幅持续存在（高水位里的 `lost` 标记）。
5. 记录真实丢失量：杀进程前最后一条消息是否在快照里 → 回填 RPO 实测。

## D 恢复流程
1. 在 C 的横幅里点某份快照的「恢复」：应先出现确认文案（写明「快照只含文字，图片和附件不可用」），点「确认恢复」才开始。
2. 进度 `正在恢复… i/N`，可点取消；中途取消后：会话列表仍是恢复前状态，`snapshots/` 里没有新增损坏文件。
3. 完成后：会话列表恢复；文字内容与快照一致；带图片的会话里图片显示为附件不可用，不崩溃；进行中的回复显示为已停止；横幅消失；toast 提示条数。
4. `snapshots/` 里应多一份 `pre-restore-<ts>.json`（若恢复前库里有会话）。
5. 再杀进程重启：不再提示丢失（高水位已按恢复后的数更新）。

## E 恢复的故障路径
1. 手工破坏一份快照（`run-as` 改一个字节）：列表里该份标「已损坏」且没有恢复按钮。
2. 在恢复进行中把分区填满（备份写入失败）：应提示「没能先备份当前状态…已停止」，现有数据不变。
3. 恢复进行中杀进程：重启后现有数据要么是恢复前的、要么是完整恢复后的，不能是半个库（单事务）。
4. 点「知道了，不再提示」：横幅消失，之后不再提示；此后若又被清除能再次提示。

## F 用户自己删光（不得误报）
1. 设置里「删除全部会话」→ 重启：不出现丢失横幅。
2. 逐条删除最后一条会话 → 重启：不出现丢失横幅。
3. 导入整包替换为一个空包 / 小包 → 重启：不出现丢失横幅。

## G 摘要自愈
1. 用 Chrome DevTools（`chrome://inspect`）连 WebView，在 Application → IndexedDB → `chat-demo` 里清空 `sessionSummaries`。
2. 重启应用：会话列表应完整出现（不是欢迎页，也不是丢失横幅）。
3. 删除其中一条摘要而保留会话：重启后后台补齐，列表刷新出现。

## H Web / iOS 回归（不应有任何新提示）
- Chrome 浏览器、iOS 壳：保存、刷新、删除都正常；无丢失横幅、无空间横幅；诊断日志里没有 `protection.snapshot-*` 噪音。
- 清 localStorage 后刷新：不提示（已知盲区，预期行为）。
