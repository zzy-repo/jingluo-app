# #839 问题 1：已登录账号「退不出去」

环境：Android 13 **模拟器**（非真机）。消费网关指向本机假 sub2api（`-PconsumeBase=http://127.0.0.1:18839 -PallowLoopbackConsume=true`，
带「不可分发」标记的联调包，仅本机使用）。假服务：登录成功，`/user/profile` 正常，**`revoke-all-sessions` 故意不回**（模拟服务端卡住 / 网络很慢）。

## 现象与原因

`signOut()` 原来是：`await` 撤销请求（write 档 20s 超时）→ `await` 回查 `/user/profile`（read 档 10s）→ 才清本地登录态。
撤销请求一旦拖住，点完「确认退出」界面要等到超时才变，用户看到的就是「退不出去」。

## 实测（同一流程：登录 → 设置 → 账号 → 退出登录 → 确认退出）

| | 点「确认退出」到界面回到登录表单 |
| --- | --- |
| 修复前（`origin/main`） | **20148 ms**（5s 时仍是已登录页；22s 才变） |
| 修复后 | **26 ms**（1s 截图已是登录表单） |

假服务端日志：修复后撤销请求照样发出，且带的是退出前的 token（`auth=Bearer at-fake`）。

## 退出后重启：等几秒不会登回去，立刻杀进程可能会

杀进程再拉起，检查 `chat-demo:auth-token` 与界面：

| 退出后多久杀进程 | 次数 | 重启后仍是已登录 |
| --- | --- | --- |
| ≥ 3 s | 3 | 0 |
| ≤ 1 s | 5 | **3** |

也就是说：退出后等几秒再重启，不会被登回去；**点完退出立刻杀进程**，有可能凭据还没落盘（见「未覆盖」）。

## 未覆盖 / 已知

- **真机未测**，网络条件是假服务「故意不回」，不是真实弱网。
- **退出后 ≤1 s 杀进程，凭据可能还在**（5 次里 3 次）。`signOut()` 已同步写 `localStorage`，但 WebView 把它落盘有延迟，这个窗口我没有在修复前包上对照量过，不能说修复前后差多少。真实用户很少在点退出后一秒内杀进程，但这是未解决的残余风险。
- 「点退出后又自动恢复登录」没有复现，代码里也没有发现这条路径。
- 问题 2（邀请码改到「我的邀请」）不在本 PR：后端没有已知的「登录后补填邀请码」接口，见 PR 正文。
