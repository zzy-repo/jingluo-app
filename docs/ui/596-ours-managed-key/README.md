| 360 对照（DeepSeek 官方） | — | 322/312、336/312 | — |

两条要读对的地方：

1. **password 输入框 = 0**：我们的渠道的 Key 行在 DOM 上**没有输入框**（不是 disabled），
   用户填不进来这件事是结构性的。DeepSeek 官方那一格仍是 1 个（对照，见集成用例的
   `expectOnlyApiKey`），另外两个自填渠道仍是三件套。
2. **那 2 处横向溢出是对话框壳自身的（`.header` / `.main`），与本单无关**：拿**没动过**的
   DeepSeek 官方渠道做对照，两档视口下的溢出对象与数值完全一致。所以它既不是本单引入的，
   也不该由本单的用例来断言清零。

## 怎么拍的

一次性脚本（不进仓库）：起静态服务 → `chromium`（playwright）→ 390/360 两档 →
选「我们的渠道」→ 未领取态截图 → 写入「Key + 下发标记」（与 `applyManagedKey` 的落盘形态一致）→
已领取态截图 → 换 DeepSeek 官方量一次对照。
「领取」这条路本身**不发真请求**：它需要 JWT，单测里按接口逐格验过（`tests/unit/managed-key-596.test.mjs`）。
