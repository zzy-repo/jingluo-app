### 变更摘要

**注册 / 登录（用户可见）**
- 注册页新增**确认密码**与**密码可见**切换（眼睛按钮：睁眼=正在显示，闭眼=已隐藏）
- 两次密码不一致时**一个注册请求都不发**，就地提示；确认密码只做本地校验，不进请求体
- 登录页复用同一个密码输入组件（眼睛按钮），但**不**加确认密码字段
- 切换可见性只改输入框类型、不重挂载，光标回到原位置；提交后 / 切 tab / 离开卡片自动恢复隐藏

**模型来源 · 内置服务（用户可见）**
- 内置服务子页**不再显示 Key 区**：Key 由服务端下发，用户不用看也不用填（输入框 / 掩码 / 「重新领取」按钮都不再出现）
- 改为**后台自动对齐**：启动时跟着登录态对齐；发送被拦时打开设置会自动再对齐并清掉提示
- 子页补一句状态文案（Key 由服务端下发 / 正在对齐 / 已对齐+尾号）；来源之间来回切换不丢已填数据

**模型来源 · 第三方服务（用户可见）**
- **取消协议二选一**：不再要用户手选协议，改为**自动适配**（按服务地址 / 模型名 / 上次判定 / 既有配置依次判定，兜底 OpenAI 兼容）
- 发送时只做本地同步判定（零网络零等待）；设置页进入第三方子页才在后台探一次，失败不改配置不落缓存
- 协议变化时把已填的「服务地址 / 模型」搬到对应槽位，内容不会凭空消失

**忘记密码（用户可见，本期覆盖前 3 步）**
- 登录卡底部「忘记密码？」→ 卡内小页：填邮箱 → 发送重置邮件
- 空邮箱本地拦下不发请求；成功提示「重置邮件已发送，请查收邮箱」
- 失败时**原样展示服务端原话** +「密码重置暂未开通，请联系客服」；只有传输层失败才退回归一化文案（不误报「未开通」）
- **重置页（邮件深链）本期不做**：App 未配 app-link，服务端重置链接指向面板页面，本 App 收不到；待深链能力就绪后一并做

## 4. 变更摘要的来源（只写**这一版真的包含**的改动）

口径（`docs/RELEASE-CHECKLIST.md` P4：「CHANGELOG 只写这一版真实包含的改动」）：

```bash
# ① 上一个已发布 tag 到本次合并提交之间的全部提交（不是到分支头 —— 分支头会漂）
LAST=$(git describe --tags --abbrev=0 --match 'v1.4.*' v1.4.9 2>/dev/null || echo v1.4.9)
MERGE_SHA=<合并进 main 的提交 sha>
git log "$LAST".."$MERGE_SHA" --oneline --no-merges

# ② 只取用户可见的两类（feat / fix）；test / docs / chore 不进用户正文
git log "$LAST".."$MERGE_SHA" --pretty='%s' --no-merges | grep -E '^(feat|fix)'

# ③ 用户看得见的那部分要有出处：每个 feat 后面括号里的 issue 号即出处
```

填写规则：

- **只写 `feat` / `fix` 且用户能感知的**；`test:` / `docs:` / `chore:` 一律不写进用户正文（可以留在 CHANGELOG 的内部备注里）。
- 每条一句话，说「用户现在能做什么 / 不再遇到什么」，不写提交标题原文。
- 同一类改动合并成一条，别按 commit 逐条列（上一版就是这么写的：修复 / 界面 / 登录 三段）。
- **没有合进 main 的功能一个字都不许写**（1.4.7 事故：版本 PR 把未合入的 UI 写进了变更记录）。
- 版本 PR 里同步 `CHANGELOG.md` 的同版本小节 —— 它同时是 dl 的 `meta.changes` 与 Release 正文的来源
  （`scripts/release-check.mjs` 第 3 项会验 `CHANGELOG.md` 有没有 `## 1.4.12` 段）。
