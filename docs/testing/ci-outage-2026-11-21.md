## 1. 替代验证路径：谁能跑 / 跑什么 / 贴什么

### 1.1 先分清「哪一层能用本地替代」

| 线 | 覆盖什么 | 谁能跑（前置） | 本地能不能等价 | 在哪一节 |
| --- | --- | --- | --- | --- |
| **A 线：发布与仓库卫生** | 8 道门禁（引用/行尾/卫生/私有发布根/签名配置/发版自检/截图引用/阈值收敛） | 任意装了 **Node ≥ 22** 的机器；**不需要浏览器、不需要 JDK**（`check:keystore` 走 `--config-only` 降级档）、不需要网络 | **能**（本轮 8/8 实测） | §1.2 |
| **通用代码层** | `tsc` / `oxlint` / `unit` | 同上 + 已装依赖（`pnpm install`） | **能，但有超时盲区** | §1.3、§2 |

本轮实测：`tsc` exit 0（无输出即通过）；`oxlint` `Found 0 warnings and 0 errors. … 278 files`、

### 1.4 证据格式：贴什么才算数

**每条证据 = 命令 + 最后一行输出 + exit code，三样缺一不可。** 不许写「应该没问题」「本地测过没问题」——
这两句话无法复核，等于没写。

模板（照抄）：

````text
$ node scripts/check-eol.mjs
check:eol OK —— 扫描 1307 个会进仓库的文本文件（git 跟踪 + 未跟踪未忽略），无 CRLF 行尾
exit=0
````

另外四条硬要求：

1. **写清在哪个 commit 上跑的**（`main@253dae31` 这种写法），不然「本地绿」对不上任何东西；
2. **写清 worktree / 是否干净**（`git status --short` 的输出为空，或者把脏的那几行贴出来）；
3. **跑的是脚本原文，不许改判据、不许加 `--skip` 类开关**（#651 明令，见 §4.3）；
4. 输出很长时贴**最后一行**（判定行）+ 完整日志落到临时目录的路径，别贴中间过程。

## 2. 本地等价验证的已知盲区（**别让后人误判**）

### 2.1 `tests/unit/gate-negative-controls.test.mjs` 贴着超时上限

这一个是**最容易被误判成「代码红」的地方**，实测两轮：

| 跑法 | 结果 | 墙钟 |
| --- | --- | --- |
| **单跑**（`node tests/unit/gate-negative-controls.test.mjs`） | `pass 15 / fail 0`（`tests 15, cancelled 0, skipped 0, todo 0`） | **340.1s** |
| **经 runner**（`node tests/run-layer.mjs unit`，默认 `--timeout-ms 180000`） | `<< TIMEOUT tests/unit/gate-negative-controls.test.mjs (180058ms)` → `Total 1: PASS 0, FAIL 1 … elapsed 360404ms` | **360.4s**（两次 180s） |

**注意 runner 那一行是「超时」不是「断言失败」**：它先 `✖ … (179697.831831ms)`、
`Promise resolution is still pending but the event loop has already resolved`，
再按 flaky 判据**自动重跑一次**（`↻ 红了（180070ms），按 flaky 判据重跑一次…`），
第二次同样被停掉，才落成 `<< TIMEOUT`。**超时是确定性的，重跑只把 180s 变成 360s，不会变绿。**

（另一台机器上的同口径实测是 `15 pass / 0 fail`、**230.8s** —— **两台机器的绝对值不一样，
但都超过默认 180s**；所以这条盲区跟机器快慢无关，只跟「它是不是贴着上限」有关。）

本机单跑的分拍耗时（说明「慢在哪」）：

| 拍 | 耗时 | 拍 | 耗时 |
| --- | --- | --- | --- |
| N3 `build`（rspack 临时副本） | 99.4s | N4 `check:test-layout` | 31.0s |
| N2 `lint` | 60.3s | N1 `type` | 18.7s |
| N7 `test:dl-release` | 58.8s | N5 `check:test-duplication` | 15.8s |
| N8 `check:keystore` | 39.0s | N10 `check:capabilities` | 12.5s |

**判读规则（照这个顺序看，不要跳步）：**

1. 看到它红，**先看是不是 `<< TIMEOUT`**（runner 的判定行），而不是断言失败 ——
   `<< TIMEOUT` 意味着「进程被停掉，断言根本没跑完」，**这不是代码红**；
2. 是超时 → 用 `--timeout-ms 300000` **单独**跑它（`node tests/run-layer.mjs unit --only gate-negative-controls --timeout-ms 300000`）；
3. 还是超时 → 才怀疑代码；仍未超时但变红 → 那才是真红，按 `docs/TESTING-POLICY.md` §6 记「命令 + 最后一行 + 时间戳」并开单。

**根治方向（两条，都不动断言）**：
- **a.** 给 CI 的 unit 步显式抬 `--timeout-ms 300000`（与 L1 分片的 420000 同风格）；
- **b.** 把它拆小：N3 / N7 / N2 这类重拍（99s / 59s / 60s）拆成独立文件，让主文件回到 60s 内。

### 2.2 口径：**「本地 unit 全绿」不能当唯一判据**

两个方向都会错，必须一起写清楚：

- **本地红 ≠ 代码红**（§2.1：超时被当成失败）；
- **本地绿 ≠ CI 会绿**（本机比 CI 慢 ⇒ 本机绿说明有余量，但反过来，本机绿**不能证明**
  CI 的 `golden` / `integration`×6 会绿 —— 那两层本地根本跑不了，见 §1.1）。

所以「本地等价验证」的结论要写成**分层的**：
「A 线 8/8 绿 + type/lint 绿 + unit 除超时外全绿（超时项单跑 15/15 绿）」，**再加上**一句
「`golden` / `integration`×6 / `flaky` 未验，已进 §3.3 补跑清单」。**缺最后这句就是假绿。**

```bash
# ① 窗口内的 merge commit 清单（committer 时间倒序；+08:00 是本机时区，UTC 见下一列）
git log origin/main --since="2026-11-21T07:41:00Z" --pretty=format:'%h|%cI|%s' | cat
# ② 某个 commit 到底改了哪些文件（判断「纯文档 / 代码」）
git show --stat --oneline 376b1239
# ③ 云端那次的 9 个 job 是不是真的零步（要 gh 有 repo 权限）
gh api repos/zzy-repo/deepseek-app/actions/runs/44881853792/jobs \
  --jq '[.jobs[]|.steps|length] | "jobs=\(length) zeroStep=\(map(select(.==0))|length)"'
# → jobs=9 zeroStep=9
```

判据：**`zeroStep` 等于 `jobs`** ⇒ 这次合并「云端从未验证」。若 `zeroStep` 小于 `jobs`，
说明那一次其实跑了一部分（§0 的 07:41:29Z 就是这样：8 个跑了、第 9 个没跑），**别一刀切成「全没验」**。

### 3.3 恢复后要做的补跑清单（按这个顺序，不许跳）

1. **先对 `main` 跑一次完整云端 CI，确认全绿**（基线）。基线不绿就别往下走 ——
   否则后面每个 commit 的红都分不清是自己带来的还是继承的。
   ```bash
   gh workflow run ci.yml --ref main    # 或等下一次 push；判据是 9 个 job 的 steps 非空
   ```
2. **对 §3.1 每个 merge commit 至少跑一次「它那一行写的层」**，把结果填回该行的「补跑」列，
   写成 `🟢 绿 / 🔴 红（开 #xxx）/ 🟡 需修`。逐条见 §3.1 最后一列，总口径是这张对照表：

   | 这一行改了什么 | 补跑该跑哪层 |
   | --- | --- |
   | **纯文档**（只动 `docs/**`、`CHANGELOG.md`：#716 / #719 / #723 / #730 / #741） | `doc gates only` = `check:doc-refs` + `check:eol` + `check:hygiene`（§1.2 里纯 Node 的那几道，不需要云端） |
   | **只动 `tests/**` / `scripts/**`**（#718 / #724 / #732 / #736） | `unit`；改到哪一层就跑哪一层 —— #736 动的就是 `golden`，所以它必须跑 `golden`，别只跑 `unit` |
   | **动 `src/**` 业务**（#720 / #721 / #726 / #731 / #734 / #737） | `unit` + `integration`；有渲染 / 样式 / 截图改动的再加 `golden`（#721 / #731 / #734）；#734 另需人工复核 `check:doc-refs` |
   | **构建 / 发布元数据**（#729） | 上述相关层 + `check:legacy` / `check:bundle-target` + `verify:apk`（版本号与 versionCode 必须落进产物） |

3. **任何红 → 开单，不许直接改判据。** 红单里必须写清「是这次合并带来的，还是继承的」
   —— 用 `git log <commit>..main -- <路径>` 证明那段时间该路径有没有别人的提交。
4. 判据提醒（#723 §5 已写）：**「job 的 `steps` 非空、runner 名非空」才是「跑过了」**，
   不是「9/9 绿」。零步的绿是不存在的，零步的红也不说明任何代码问题。

### 3.4 这张台账已经兑现的第一个代价：`main` 的 `check:doc-refs` 红了

**这是本文档写作时实测到的既成事实，不是为了说明观点编的例子：**

`main@253dae31` 上 `node scripts/check-doc-refs.mjs` **exit=1**：

```text
FAIL 2
  docs/consume-676-contract-audit.md:38  src/services/consume/auth.ts:429
      起行 429 是空行（文件 571 行）
  docs/consume-676-contract-audit.md:49  src/services/consume/auth.ts:144
      起行 144 是空行（文件 571 行）
```

**归因（已核实）**：`src/services/consume/auth.ts` 在 `292fafe6` / `3bf72f77` 上
`toConsumeUser` 还在第 144 行、`revokeAllSessions` 还在第 429 行；**#720（08:02）**插入
deviceId 相关代码后整体下移，两处引用就指到了空行。也就是说：
**一个代码 PR 在「云端不跑」的窗口里合入 → 同一次合并把另一份文档的行号引用搞红，而没有任何
一道门禁在合入前告诉过任何人。** 这正是「纯文档 PR 可以破例、代码 PR 必须本地跑过」的理由（§4.2）。

本 PR 顺手修了这两处（纯文档，只改行号，不改判据）；**同文件里另有 4 处引用语义上已经偏了
（`register` / `login` / `loginWithTwoFactor` / `refresh` 四个行号），门禁不管这一类，留作
follow-up 单独收口**，不在本 PR 里顺手改 —— 混进来就没人 review 得动了。

### 3.5 补跑判读口径（先读这段，再判红）

补跑一开，最先出现的往往**不是**「代码红」，而是下面三种「看起来像红、其实不是」。按顺序判，别跳步：

**① `unit` 层出现 `<< TIMEOUT` → 先判超时，别判红。**

`tests/run-layer.mjs unit` 的默认批内超时是 180s，而 `tests/unit/gate-negative-controls.test.mjs`
本机实测 **230.8s / 340.1s**（§2.1 两台机器），**贴着甚至越过上限**：runner 打的是
`<< TIMEOUT …`，意味着「进程被停掉、断言根本没跑完」，**这不是断言失败**。
处置顺序固定：先看 runner 判定行是不是 `<< TIMEOUT` → 是就用 `--timeout-ms 300000` **单跑**该文件 →
仍超时才怀疑代码。根治在 **#733**（车道 C）处理中，该单标题就是
「gate-negative-controls 负载下撞穿 180s 批内超时，伪装成 main 红了」。

> 反向数据点同样要记住：同一条用例在云端 `44880077535` 那次是**真跑**的，**59.9s 就 PASS**
> （本机 230–340s）。所以「本机超时」既不等于「CI 会超时」，也不等于「CI 已红」——
> 判红之前依次看三样：**steps 非空**（§3.3 第 4 条）→ **墙钟与超时上限**（本节 ①）→ **断言**。

**② 文件已在 `flaky-registry` 里登记的 → 按既有 flaky 判读，不算新增红。**

登记簿是 `tests/flaky-registry.json`（形状与判据见 `scripts/flaky-registry.mjs` 文件头与
`docs/TESTING-POLICY.md` 第 11 节），三类各管一段：`same-runner`（同 runner 首次红、重跑绿）=
自动重跑 + 登记，连续 3 次进 quarantine；`cross-runner`（同 commit 同用例、不同 runner 结果不同）=
必须改成等终态，**禁止加 sleep / 抬超时**；`infraSignatures`（#611）登记的是「runner 自己崩了」
的证据串，命中判 INFRA + 该文件单独重跑一次，**不放行任何文件**。
截至本文写作，登记簿 `tests` 字段只有 **1** 条（`tests/unit/capabilities-docs-sync.test.mjs`）
—— **不在簿里的，不许口头说「它本来就是 flaky」**：那等于没判，按新增红处理。

**③ 补跑红 → 开单，不许改判据。**

判据同 §4.3（不许改断言、不许加 `--skip` / `--only`、不许把门禁从 `ci.yml` 摘掉、不许把超时改判成跳过）。
红单必须写清三件事：**命令 + 最后一行输出 + exit**（§1.4）、**在哪个 commit 上跑**、
**是这次合并带来的还是继承的**（用 `git log <commit>..main -- <路径>` 证明那段时间该路径有没有别人的提交）。
另加一条：**一行一个结论，别汇总成「都绿了」** —— 层没跑齐（例如 `integration` 6 分片只跑了 2 片）
就写「未验」，不许拿 `unit` 的绿替代 `integration`（理由见 §1.1 那张表）。

## 4. 这段期间的合并纪律（写给后来人）

### 4.1 破例的三个条件（缺一不可）

只有在**同时**满足这三条时才允许在「云端不跑」的状态下合并：

1. **内容等价已验证**：本地跑过与被改文件相关的层（纯文档 → §1.2 的 8 道；代码 → §1.3 + 相关层），
   并贴了「命令 + 最后一行 + exit」；
2. **破例理由写在 PR 正文里**：一句话说明为什么这次不能等（例：
   「计费停摆，9 job 零步，本地 8/8 门禁绿，等恢复会阻塞 #xxx」）；
3. **留痕**：PR 正文 + 车道单（#651 / #652）各记一笔，恢复后在 §3.1 台账里能查到。

### 4.2 风险分级：纯文档可以走破例，代码 PR 必须本地跑过对应层

| 改动类型 | 破例可否 | 最低验证 |
| --- | --- | --- |
| **纯文档**（只动 `docs/**`、`CHANGELOG.md`） | **可以** | §1.2 的 8 道全绿（本轮实测 8/8） |
| 纯用例（只动 `tests/**`） | 谨慎 | `unit`（或 `integration`）+ 负向对照，且**必须排除 §2.1 的超时假红** |
| 代码（`src/**`、`shared/**`、`config/**`） | **不建议**，需要更强理由 | §1.3 三条 + 受影响层；改了行号还可能打破文档引用（见 §3.4） |
| workflow / CI / 设置 | **不许** | 改门禁本身在门禁失灵期间改，等于没人验门禁 |

### 4.3 不许为了「看到绿」动判据（#651 明令）

- 不许改断言、不许加 `--skip` / `--only` 之类的绕过开关、不许把门禁从 `ci.yml` 摘掉；
- 不许把「超时」改判成「跳过」（§2.1 那条：抬 `--timeout-ms` 是**换配置**，
  `docs/TESTING-POLICY.md` §6 允许并要求写明换了什么；`skip` 不是）；
- 不许把「9 job 零步」解释成「基础设施问题所以不用验」—— **零步 = 没验**，进 §3.3。

### 4.4 恢复当天的第一件事

不是补发布、不是重跑历史 run，而是**把 `main` 的最新一次跑绿**（§3.3 第 1 步），
然后按台账逐条补跑。历史 run 不必全量重跑：**重跑会再计分钟**，
`gh run rerun <run-id> --failed` 只对「最新 main + 当前 open PR 的 head」用（口径同 #723 §5）。
